## 今日の所感

- 今日の回は上級 第30回（a03-brew-chart、用語「濃さと収率」）。柱 = terms、`word`/`ask`/`hook` は下書きのまま。回のテーマは「濃さと収率は別の軸で動く — 濃さはお湯の量、収率は挽き目」
- 抽出法は、昨日（10-27）がマグで浸漬だったので、ローテーションの 0-count（水出し / マキネッタ）を検討。水出しは冷水で「お湯の量」の話と合わない、マキネッタは水量が固定（チャンバー）で「お湯の量を動かす」と合わないため、1-count の中からペーパードリップを選択。家で淹れる人の最も素直な器具で、hook「お湯の量だけを動かす」が自然に成り立つ
- 事実の確認: SCA Brewing Control Chart（濃さと収率の 2 軸独立）/ Wikipedia Coffee extraction（水量が主に濃さを動かす）/ Perfect Daily Grind（挽き目が収率を動かす、適正帯で甘み・角丸く、未抽出=酸・過抽出=苦）で、本回の対比の裏付けを取り、`lesson.sources` に残した
- 読み: 「収率(しゅうりつ)」「出方(でかた)」「役割(やくわり)」を `data/tts-readings.json` に追加（迷ったら足すルール）

## 戦略更新提案

本回のレビューで「ルーチンが変えてはいけない所」として繰り返し指摘された項目を、人の PR で検討する価値がある候補として挙げる:

- 用語回（`pillar === "terms"`）の表紙で、`topic` を表紙に出さない（「濃さだけが変わる」が答えの先出しに見える問題）。表紙は `word` + `ask` の問いだけに絞り、`topic` は場面2 以降に移す案
- 用語回の場面2 の見出し「なぜ変わる？」を、用語回では「○○ってなに？」や「どこが動く？」など、中身に合う問いに差し替える案
- 用語回で `effect` の情報を場面2 と場面4 に両方出す現仕様を、場面2 からは外し、場面4 の山場で初出にする案（B と C が複数周で「山場が立たない」と指摘）
- `visual.compare` の `left.strength` / `right.strength` だけでは「2 つのつまみの役割の違い（濃さ軸 vs 収率軸）」を描き分けられない問題。カップ色以外の第 2 軸（例: メーター 2 本、ラベル付き軸、色相違い）を追加する schema 拡張案
- `motion.compare` を場面2 で「お湯側の濃さ」だけでなく「挽き目側の収率（味の出方）」も同時に動かせるようにする案（E が複数周で「片輪」と指摘）
- `src/looks/art-words.mjs` の tipArts マッピングで、「細かく」「粗く」を別の挿絵（細挽き・粗挽きの粒度差が分かる絵）に分ける案。E が複数周で「grinder が 2 連で向きが絵で区別できない」と指摘
- `src/looks/art-words.mjs` の ratio 挿絵が「粉のスプーン＋ケトル」で、お湯だけを動かす行に粉が描かれる問題（E が複数周で指摘、2026-10-27 オーナー発注にも関連）。お湯単独の挿絵（ケトルのみ）に差し替える案
- 次回予告の読み上げを、下書きの `ask` の形（例「足し湯で薄めると？」）に揃えて、単体で何の回か分かる形にする案（C が複数周で指摘）
- 用語回で 1 本の中では budget 不足で用語（収率など）の完全定義ができない問題。シリーズのオンボーディング回（a01 より前）に、全シリーズで使う一般語（挽き目・濃さ・ペーパードリップなど）の説明回を 1 本置き、以降は前提にできるようにする案
