# シリーズ地図「味をコントロールする技術」

コーヒーアカウント（IG @open_ground_coffee_roasters / YT @OpenGroundCoffee）の毎朝の動画は、2026-09-25 のオーナー依頼で **1 本ずつ見ていくとコーヒーの味を自分で動かせるようになるシリーズ**になった。この文書はその地図（カリキュラム）。

- **正本は `data/curriculum.json`**。並び順がそのまま放送順。この表は人が読むための写しで、`scripts/content-format.test.mjs` が「全部の回がこの順で載っているか」を検査する（回を足す・並べ替えるときは両方を直す）
- 46 回。**初級 13 回 → 中級 14 回 → 上級 19 回**。用語だけを解説する回（**用語**）が 10 回、**理論の回**（柱 `theory`「抽出の理屈」。2026-10-28 から）が 6 回ある
- 各回は「**変えることは 1 つ**（`lesson.hook`）」「**なぜ変わるか**（`lesson.why`）」「**上げると / 下げると味がどう動くか**（`lesson.effect`）」を持つ。表紙は**大きい一言＋問い**（`lesson.word` + `lesson.ask`、例「湯温を下げると？」）で、IG のグリッドを見ただけで何の回か分かる
- **レシピの数字（g・ml・秒・分・℃・比率・挽き目の段数）は動画にもキャプションにもナレーションにも出さない**（2026-09-26 オーナー決定「具体的なレシピの何グラムでとか…そういうのはいらない」）。`scripts/content-format.mjs` の `recipeNumberReason` が機械的に弾く。量や温度は「高め / 少し / 長め」と言葉で言う
- 用語回も「今日すぐ試せる 1 つ」を持つ（例: TDS の回は「粉を少し増やす → TDSが上がり濃く感じる」）。言葉だけ覚えて終わらないようにするため

## 並べ方の考え

1. **初級**は「味を動かすつまみ」を 1 つずつ触る。最初に「抽出」という言葉（第1回）と「量る」「比率」（第2〜3回）を押さえ、挽き目 → 湯温 → 時間 → 蒸らし → 注ぐ速さの順に 1 つずつ動かす。第10〜11回で「浸す淹れ方」を知り、第12〜13回で「酸っぱい / 苦い をどう直すか」にまとめる
2. **中級**は初級のつまみの「理由」と「組み合わせ」。未抽出・過抽出という言葉（第14〜15回）で初級の直し方に名前を付け、焙煎度と湯温、注ぐ回数・位置、蒸らしの量と時間、ドリッパーの形、フレンチプレス・クレバー・金属フィルター、水、アイス、最後の一回しへ進む
3. **上級**は「濃さ」と「溶け出し方」を分けて考える。TDS（濃さ）と抽出収率（溶け出した割合）を 1 回ずつ解説し、「濃さは比率、味の出方は挽き目」という分け方（第30回）、バイパス、微粉、落とし切らない、注ぐ高さ、浅煎りの高温、最後に「1 回に 1 つだけ変える」で自分のレシピ作りに着地する。第33回からは、その間に**理論の回**（下の「理論の柱」）を 2〜3 日に 1 回はさむ

前の回を見ていると次の回が分かるように、各回は前の回で覚えたこと（言葉・つまみ）を 1 つだけ使って先へ進む。

## 毎朝どう使われるか

| 場面 | 何が起きるか |
|---|---|
| 朝ルーチン（07:30） | `node scripts/next-episode.mjs` が「今日の回」＝**最後に出た回の次**（まだ何も出ていなければ第 1 回）を出す。ルーチンはその回を書く（`lesson.episode` にその id）。変える条件（`hook`）と柱は変えない。器具が教える回（表の「固定」）は抽出法も変えない |
| 検証 | `validate-content.mjs` と本番の `generate-data.mjs` は、`lesson.episode` が今日の回でないと NG にする（飛ばし・重複を防ぐ） |
| ルーチンが原稿を出せなかった朝 | 同じ「今日の回」の常備原稿（`data/curriculum.json` の `lesson`）がそのまま出る。**差し替えの日もシリーズは 1 回ずつ進む** |
| 出た回の記録 | 投稿後に `data/performance-history.json` の `content.episode` に残る（片方の投稿が失敗しても、出た分は記録する）。`next-episode.mjs` は**最後に出た回の次**を選ぶ（その日より前の投稿だけ。再実行で同じ日を数えない）。投稿できなかった日は記録が無いので、翌日に同じ回をもう一度出す |
| 全部出たあと | 最後の回（いまは第 46 回）の次は第 1 回に戻り、表の順にもう一周する（シーズン 2） |

動画の中では、表紙（1 枚目）に「初級 第4回」、最後の画面とキャプションに「次回 ○○」（次の回の表紙の問い）が出る。流れは 表紙 →（まず前提）→ なぜ変わる？ → 図解 → 味はこう変わる（上げると / 下げると）→ うまくいかない時 → 締め。

## 理論の柱（`theory`「抽出の理屈」。2026-10-28 オーナー発注）

> 「コーヒーのアカウントで『収率って何』っていうポストがめっちゃバズってます。多分みんなドリップの時の理論とかそういうのも結構興味あるんじゃないかなって思いました」→「A（理論の回を定番の柱にして週 2〜3 回）。よく分析して、なんでバズったか、どこが良かったのかとかも全部見て、今後のポストに参考にしてください」

ドリップの**理屈**（溶け方・ムラ・落ちる速さ・溶ける順番・温度の下がり方など）を 1 つ取り上げ、**「だからあなたの一杯はこう変わる」まで**つなげる回。言葉の説明で終わらせない。分析は sns-hub `docs/operations/2026-10-28-coffee-theory-pillar.md`。

- **頻度**: 2〜3 日に 1 回（週 2〜3 回）。曜日で選ぶ仕組みは無く、**この表の並び**で決まる（理論の回の間に、ほかの回を 1〜2 本はさむ）。投稿できなかった日は同じ回を翌日に出すので、曜日はずれても間隔は保たれる。`scripts/content-format.test.mjs` が「理論の回の間はほかの回 1〜2 本」を検査する
- **型（伸びた回から取った決まり。どの回にも使うが、理論の回は必ず）**:
  1. **答え（`topic`）は味の言葉**。できれば「甘くなる / 甘みが出る」側。用語の言い換え（「TDSが上がり…」）や、誰でも知っている結果（「粉を増やすと濃い」）を答えにしない
  2. **図は「自分の一杯がどこにいるか」**を見せる（酸っぱい / 甘い / 苦い、未抽出 / 適正 / 過抽出 のような 3 区分の目盛りやグラフ、または 2 杯の比べ）。ナレーションで区分ごとの味を言う（「低いと酸っぱく、ちょうどで甘く、高すぎると苦い」）
  3. **前に出た言葉を 1 つ使う**（未抽出・過抽出・収率）。新しい言葉は 1 本に 1 つまで
  4. **常備原稿にナレーション（`title` / `why` / `visual`）まで書いておく**。ルーチンが原稿を出せなかった朝も、機械の読み上げ文（「今日の用語は、TDS。…」）にならない
  5. 1 本 1 つの理屈。数字は出さない（いつもどおり）
- **柱の扱い**: 用語回（`term` を持つ回）は柱が `terms` のまま（テストが固定）。理論の回は `term` を持たず、表紙の見出しは【抽出の理屈】になる。PDCA の柱別の集計（`pdca-summary.mjs` の「柱別」）に「抽出の理屈」として出る
- **判定**: 最初の理論の回（第33回「酸味と苦味が同時に？」）の放送日から 14 日目にオーナーが、Instagram の保存数とフォロワー増で続けるかを決める（日付は上のメモ）
- **ネタが尽きる前に足す**: いまの表は第 46 回で終わり、その次はシーズン 2（第 1 回から）に戻るので、**理論の回はそこで止まる**。続けるなら、第 46 回が出る前に人の PR でこの表の後ろに回を足す（ルーチンは `data/curriculum.json` を書けない）

## 前提（「まず前提」のスライド。2026-10-19 オーナー依頼）

> 「コーヒー初心者の人ってさ、クレバードリッパーとか知らないと思うんだよね。それで、どういう原理でコーヒーが抽出されるかも、多分わかってないんだよね。だから、動画を見たときに前提知識が必要となるようなものは、ちゃんと前提知識もその動画で説明するか、説明が長くなるなら、その動画を出す前にもう一つ動画を作って説明できるようにしようよ。」

見る人は昨日までの回を見ていない初心者、と考える。器具の名前（クレバー等）・淹れ方の原理（浸漬式と透過式等）・専門用語を知らないと分からない回は、次のどちらかにする。

| 線引き | どうするか | 書くところ |
|---|---|---|
| **1 行（24 字）と図 1 枚で言える** | その動画の中で、**表紙の直後**に「まず前提」のスライドを 1 枚入れて先に説明する（10 秒前後） | 回の `lesson.premise`（`term` 14 字・`say` 24 字・`visual`）。ナレーションは `lesson.narration.premise` |
| **1 行では言えない**（説明だけで 1 本分） | **前日に説明回を出す** = この表で**すぐ前**に説明回を置く。本番の回の前提スライドは短い 1 行にして、`premise.ref` に説明回の id を書くと、動画が「わからない時は、前回の動画を見てください」と言い、キャプションにも「わからない時は前回の動画「…」へ」が入る（すぐ前の回でなければ「第○回の動画」） | `premise.ref`。並べ替えはこの表と `data/curriculum.json` を人間の PR で |

- 1 本に前提は 1 つまで。ほかの言葉は文の中で言い換える（例「クレバー（浸して待ってから落とすドリッパー）」）か使わない
- **用語回**（その言葉自体を説明する回）は、その言葉を前提にしない
- 回に `premise` があると、朝ルーチンの原稿もその前提を外せない・変えられない（`term` / `say` / `visual` / `narration.premise` が同じでないと検証 NG で常備原稿に差し替わる）。ナレーションでは「浸漬」を「しんし」と読ませる（`toSpokenJa`）。常備原稿にも入っているので、ルーチンが動かなかった朝も説明は出る
- 毎朝の点検（今日の回と明日の回）は `docs/routine-prompt.md` の手順 2「0.5 前提知識の点検」。説明回が足りないと分かったら、ルーチンはレポートの「戦略更新提案」に書き、並べ替えは人間がする

いま前提を持つ回は、下の表の「回」に **前提「…」** と書いてある（第22回 フレンチプレスの浸す時間・第24回 金属フィルター = 浸漬式と透過式、第23回 = クレバー、第25回 水を軟水に = 軟水と硬水）。

- **第22回と第24回は同じ前提（意図的）**: 間に第23回があり、どちらも「昨日までを見ていない初心者」が見ても分かるように、それぞれの回で同じ説明をする（`ref` で前の回へ送らない）
- **第25回の前提「軟水と硬水」の出典**（2026-10-20 確認）: 硬度は主にカルシウムとマグネシウム、60 mg/L 未満が軟水（WHO「Hardness in Drinking-water」2011）。日本の水道水の硬度は全国 5,835 施設の中央値 44 mg/L（食品安全委員会「清涼飲料水評価書 カルシウム・マグネシウム等（硬度）」2017）なので「多くが軟水」と言える。「ほとんどが軟水」は言い過ぎ（東京は平均 60 程度で境目、関東は高め）。図は目盛り（scale）で、針は軟水の側。本編の図解（compare = 硬水と軟水の味）と同じ絵を繰り返さない
- **第23回の前提の図は「浸漬式 / 透過式」の 2 つ**で、キャプション「クレバーは浸漬式の仲間」はその図を指す。「最後に下から落とす」流れは、2 枚後の図解（浸して待つ → 落とす）が描くので、前提の図では繰り返さない
- **第25回は前提「軟水と硬水」を台本の場面②（まず前提）で言う**（`lesson.premise` ではなく `lesson.script`。下の「台本の回」）。出典は下の行のまま

## 台本の回（`lesson.script`。2026-10-20 オーナー依頼「台本どおりの場面で作れるように」）

- オーナーが場面ごとに OK した台本は、回の `lesson.script` に入れる: `{ cover: { art, narration }, scenes: [{ label?, heading, body, art, narration }] }`。動画は**表紙（問いだけ。答えはまだ出さない）→ 台本の場面（2〜5 個）を順に → 締め**になり、決まった並び（なぜ変わる？・図解・味はこう変わる・うまくいかない時）は描かない
- `body` の 1 項目は 1 行（文字列）か、`{ lead, result }`（「硬水で淹れる → 酸味が消える分、苦みが目立つ」の 2 段）。`art` は `src/looks/SceneArt.tsx` の絵の名前（`glasses` / `minerals` / `acid` / `compare` / `which`。一覧と大きさは `src/looks/safe-layout.mjs` の `SCENE_ART`）。絵は Codex の参考画像（`docs/previews/ref/soft-water-*.jpg`）をコードで描き直したもの。新しい台本の回で絵が要るときは、同じ手順で `SceneArt.tsx` に足す
- 朝ルーチンは `script` を**一字も変えずに写す**（検証が照合し、変えたり外したりすると常備原稿に差し替わる）。カリキュラムに `script` が無い回に、ルーチンが `script` を書くこともできない
- `topic` / `why` / `effect` / `tips` は台本の回でも残す（YouTube のタイトル「…？ 軟水は酸味、硬水は苦み」と記録に使う）。キャプションの本文は台本の場面の文字から作る
- 画面に入るかは `layoutProblems` が場面ごとに検査する（文字が Reels の UI の上・右のボタンの左に収まるか、絵が小さくなりすぎないか、classic のカードに入るか）
- 第25回（硬水と軟水）の台本は sns-hub `docs/operations/20261020-coffee-1021-soft-water-script-v2.json`（初見の人レビュー 3 回済み）。表紙の大きい一言は「硬水と軟水で」（6 字。`LIMITS.word` を 6 に）

## 図解の型（「なぜ変わる？」の次のスライド）

表紙と「なぜ変わる？」の次に、その日の 1 つの変化を**絵で見せる**スライドが入る（`src/cards/Diagrams.tsx`）。原稿の `lesson.visual.type` で選ぶ。表の「図解」は常備原稿の型で、ルーチンは中身に合えば別の型にしてよい。図の中にも数字は書かない（点の名前は「短い / ふつう / 長い」など）。

| 型 | 見せるもの | 向いている回 |
|---|---|---|
| `compare`（比べてみる） | 左右に 2 つのカップ。条件 → カップの濃さ（`strength` 1〜5）→ 味。今日の側に「今日はこっち」 | 粗い / 細かい、紙 / 金属、硬水 / 軟水 |
| `graph`（味の動き） | ある変数に沿って味が動く線。今日の点に「今日」。`zones` で「未抽出 / ちょうど / 過抽出」の帯 | 抽出時間、蒸らし時間、浸す時間 |
| `flow`（お湯の流れ） | ドリッパーの断面。お湯の注ぎ、粉の層、落ちるしずく（透過式）／浸かる粉（浸漬式）。注ぐ速さ・位置・高さ、粉の偏りも描ける | 透過式と浸漬式、円すいと平底、注ぎ方 |
| `scale`（目盛りで見る） | 名前の付いた帯（低め / ふつう / 高め など 2〜3 個・同じ幅）の上を、針が「いつもの位置」から「今日の位置」へ動く。数字は出さない（位置は 0〜100） | 湯温、濃さ、TDS、収率、蒸らし湯の量 |

プレビュー: `docs/previews/series-*.png`（型ごとに 1 本ずつ）。
